# 新闻怎么写

一篇新闻 = 一个文件。加新闻就是新建一个 `.md` 文件，不用改任何代码。

这个目录里的每个 `.md` 文件都会被自动收集、按时间排好、显示到新闻页。
文件名以下划线开头的（比如本文件、`_TEMPLATE.md`）不算新闻，是给人看的说明。

---

## 四步

1. 复制 `_TEMPLATE.md`，改个名字，比如 `2026-10-08-ide-v3.md`
   - 文件名随便起，不重名就行，建议全用英文/数字（避免编码问题）
   - 前面带日期只是为了文件夹里排序好看，真正的日期是文件里的 `date` 字段
2. 填开头 `---` 之间的字段（下面有说明）
3. 空一行，往下写正文
   - 段落之间**空一行**，一段对应页面上一个自然段
   - 一行写很长没关系，回车换行不代表分段
4. 存盘。刷新页面就能看到

---

## 字段说明

| 字段 | 必填 | 写什么 |
|---|---|---|
| `title` | 是 | 标题。列表卡片和详情页大标题都用它 |
| `slug` | 是 | 网址用的英文短名，全小写、用连字符，比如 `ide-ai-tutor-v2`。发布后不要改（改了就断链） |
| `date` | 是 | 日期，格式必须是 `YYYY-MM-DD`，排序靠它 |
| `category` | 是 | 只能填这四个之一：`公司动态`、`产品发布`、`技术分享`、`生态合作` |
| `summary` | 是 | 一句话摘要。列表卡片和详情页导语都用它，控制在 60 字以内最好看 |
| `pinned` | 否 | 填 `true` 就上页面顶部的滚动区；不填或填 `false` 就是普通新闻。**建议最多标 3~5 条** |

---

## 两个板块是怎么来的

新闻页从上到下就两块：

1. **顶部滚动区**（重点新闻）：只放 `pinned: true` 的那几条，自动轮播。
   一条都没标 → 这块整块不显示，页面直接从「最新资讯」开始。
2. **最新资讯**（列表）：所有新闻按日期倒序，上面可以按分类筛。

想让某条新闻上顶部，就把它的 `pinned` 改成 `true`。

---

## 配图

可放可不放。放的话：

- 文件放到 `src/assets/images/news/`，**文件名必须等于 slug**，比如 `news/ide-ai-tutor-v2.png`
- 尺寸 1200 × 675（16:9），单张压到 300KB 以内
- png / jpg / webp 都认，按文件名匹配，不看扩展名

不放图不会裂，页面上会显示一个占位框，写着这个位置该放什么图 —— 这样也不会产生 404 请求。

## 改完自检

不用额外命令 —— 校验是**跟着开发服务器/构建一起跑**的：

```bash
npm run dev     # 改完存盘，看终端有没有 [news] 开头的报错
npm run build   # 上线前跑一次，构建日志里同样会点名
```

规则（写在 `src/data/news.ts` 里）：

- 缺 `title` / `slug` / `date` / `category` / `summary` 任意一项 → 点名报错，**跳过那一条**
- `date` 不是 `YYYY-MM-DD`、`category` 不在允许的几类里 → 同样跳过
- `slug` 重复 → 保留先出现的，后面的跳过
- 正文为空 → 报错但保留（标题还会出现在列表里）

跳过不会让整页打不开：合法的那几条照常显示，被跳过的会在终端里以
`[news] content/news 下有 N 处问题，相关文件已跳过：` 开头列出来，照着一行行改就行。

一条都不合法时，页面上显示的是那个设计过的空态（「内容筹备中」），不是白屏。

## 上线后想改内容怎么办

现在还不用管，流程是：改文件 → `npm run build` → 把 `dist/` 传上去。

将来内容多了、或者有别人要发稿，再考虑上后台（见项目根目录的说明）。
