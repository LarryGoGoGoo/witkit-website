# 图片放这里

把图丢进对应目录，**文件名对上就自动生效，不用改代码、不用改配置**。刷新页面即出现。

目录约定只有两条，看文件名就懂：

```
src/assets/images/
├── logo-witkit.png              顶层散放 = 全站只有一个的图
├── logo-witkit-inverse.png
├── about/                       分组 = 按页面归类
├── careers/
├── icons/
├── labs/
├── news/
├── products/
├── services/
├── systems/
```

**这里故意不列出「应该有哪些图」** —— 那份清单是生成物，
手抄一份到这儿只会两边漂移（这个文件以前就是这么烂掉的：
上面写着 `hero-visual.png`，而那个位子早改成了 `hero-bg`）。

要看图片需求清单，看**项目根目录的 `图片需求清单.md`**，
它由 `npm run docs:images` 从 `src/assets/imageSpecs.json` 生成，不会漂移。
查当前进度跑 `npm run check:images`（会列出「已就位」和「待补 + 规格」）。

## 尺寸与内容规格在哪

`src/assets/imageSpecs.json` 是**唯一真源** —— 占位框上写的尺寸/内容要求、
`图片需求清单.md`、`check:images` 的统计，全都读它，所以三者永不走偏。
加一个新图片位就先往这里加一条，别的什么都不用改。

支持格式：`png` / `jpg` / `jpeg` / `webp` / `avif` / `svg`。
扩展名写哪个都行，代码按「同名」匹配，不看扩展名。

## 为什么不用 public/images/

放在 `src/assets/`，Vite 会在构建时给每张图加内容指纹（文件名带 hash），
浏览器缓存可以永久有效，改图后用户必然拿到新版。
代价是改图后需要重新构建——官网本来就是构建后部署，不亏。

更关键的是：**没做的图不会产生 404 请求**。
构建期就确定了哪些图存在，不存在的直接渲染占位框，控制台不会有任何报错。

## 规格要求

见项目根目录 `图片需求清单.md`。核心几条：

- 一律按 **2x** 出图（显示 1440px 宽的，出 2880px）
- 单张 **< 300KB**，PNG 用 tinypng 压，照片转 WebP
- 文件名**全小写 + 连字符**，不用中文和空格
- 截图用**浅色主题**，和官网白底一致
- 敏感信息（真实邮箱、密钥、Token）必须打码
